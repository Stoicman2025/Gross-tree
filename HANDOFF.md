# Семейное дерево — заметки для продолжения работы

## Состояние (октябрь 2026)
Сайт работает на Cloudflare: https://gross-tree.stoicment.workers.dev. Секреты заданы, родственники начали вносить данные. Инструкция для владельца — `README.md`.

Последнее обновление (схема базы v2, по итогам теста с родственниками): данные «на проверке» сразу видны в дереве бледными, заметки к карточкам, объединение дублей. Сервер сам обновит живую базу v1 → v2 при первом запросе: `ALTER TABLE` + новые таблицы, существующие данные становятся `approved`. Заявки, отправленные до обновления, остаются «старого формата» (`payload.materialized` нет) и принимаются по-старому через `apply.js` + `PATCH`.

## История решений
- Старая версия (Worker + D1, не в репозитории) не работала из-за ошибки в коде: семейный код «Наша семья» уходил в HTTP-заголовке `X-Auth`, а браузер не пропускает там кириллицу. Плюс коды лежали открытым текстом в публичном репозитории.
- Сначала сделали версию на Supabase + GitHub Pages, но владелец выбрал Cloudflare: проект не засыпает, лимиты щедрее, аккаунт и автодеплой из GitHub уже есть. Supabase-код удалён.
- Фото — в **Workers KV**, а не в R2: для R2 Cloudflare требует банковскую карту, а российские карты не принимаются.
- Дизайн «Скандинавский свет» выбран из трёх концепций (артефакт https://claude.ai/artifact/EXuQ79RuJ6HGjKd5Qby9JC).
- Родственники входят по общему семейному коду, администратор один — по паролю (секрет `ADMIN_PASSWORD`). Секреты — в разделе Settings → **Variables and Secrets** (runtime), а не в Build: на этом уже спотыкались.
- Родственники в РФ, `*.workers.dev` открывается у них через VPN.
- По итогам первого теста с родственниками: (1) нельзя было вносить людей цепочкой — новый человек появлялся только после одобрения; (2) родственники не видели результата; (3) нужны заметки к карточкам. Решение: всё присланное сразу пишется в базу с `state = 'pending'` и видно бледным.

## Архитектура
- `wrangler.jsonc`: Worker `gross-tree`, `main: src/worker.js`, статика из `./public`, D1 `DB` (`family-tree-db`), KV `PHOTOS` (`family-tree-photos`), `keep_vars: true`.
- `src/worker.js` обрабатывает `/api/*` и `/photos/*`. Схема v2 (`ensureSchema`: CREATE IF NOT EXISTS + ALTER-миграции с проглатыванием ошибок «столбец уже есть»).
  - Модерация: у `people`, `parent_child`, `unions`, `photos`, `notes` — поля `state` ('approved'|'pending') и `submission_id`; у `people` ещё `added_by`. Внимание: в `unions` поле `status` — это статус брака, а не модерации.
  - `POST /api/submissions` (родственник): создаёт pending-записи (новые люди из `payload.person` и `ref.new`, связи, фото, заметку) и заявку с `payload.materialized = true` и `payload.created = { main, refs: {индекс в add: id} }`. Правки неподтверждённых людей и удаление неподтверждённых связей применяются сразу (если больше ничего нет — заявка не создаётся, ответ `{ id: null, applied: true }`). Правки полей и удаления у подтверждённых — остаются в payload для админа. Не больше 40 инструкций на анкету (лимит D1 — 50 запросов за вызов).
  - `POST /api/admin/submissions/:id/approve` (`skipEdits` — если админ уже применил правки через форму) — применяет правки и удаления из payload, переводит записи заявки в `approved`, ставит главное фото. `…/reject` — удаляет pending-записи заявки (людей — вместе со всеми их связями, фото из KV, заметками).
  - `POST /api/admin/merge {from, into}` — перенос связей, фото, заметок и заявок, заполнение пустых полей, удаление `from`. Используется и при «это уже есть в дереве» в заявке (клиент сначала объединяет, потом одобряет).
  - Заметки: родственники — заявкой `add_note`, админ — `POST/DELETE /api/admin/notes`.
  - Ответы создаются через `makeResponse` с хуком `globalThis.__ftMakeResponse` — для запуска в браузере.
  - Остальное как раньше: сессии-cookie `ft_s`/`ft_a`, хеш кода с солью, ограничение подбора по IP, проверка `Origin`, загрузка только JPEG.
- Фронтенд — ES-модули без сборки. `backend.js` — единый клиент API. Если `/api/session` не отвечает JSON-ом (локальный просмотр), `demo-server.js` запускает **тот же `src/worker.js` в браузере**: D1 → sql.js, KV → память + IndexedDB, cookie → localStorage, ответы → `FakeResponse`. Отдельной демо-логики больше нет.
- `model.js`: `isPending(id)`, `isLinkPending(p, c)`, `union.pending`, `photo.pending`, `notes(id)`. У подтверждённого человека главным фото может быть только подтверждённое.
- Отрисовка: карточка `.pending` (бледная, пунктир, бейдж «на проверке»), линия `.link.pending` (пунктир), если неподтверждена связь или любой из её людей.
- Формы: после добавления человека родственником — окно «Готово!» (добавить ещё / открыть карточку). «Изменить и принять» для новых заявок открывает форму по уже записанной pending-карточке, из payload подмешиваются только не применённые правки и удаления.
- Действия на дереве (`treeview.js`): слой `#cardActions` поверх сцены, кнопки не масштабируются. Показываются для карточки под мышью (`hoverId`) или выделенной (`selectedId`): «+ Родитель» (скрыт при двух родителях), «+ Ребёнок», «+ Супруг(а)», «+ Брат, сестра», в углу — заметка. Действия вызывают `addRelative()` из `drawer.js`. На касаниях первый тап → `select(id, { preview: true })` (без профиля, дерево подстраивается через `ensureVisible`, подсказка показывается один раз), второй тап открывает профиль. Значок `.note-badge` на карточке показывает число заметок; клик по нему открывает заметку.
- Быстрая заметка (`quick-note.js`): на компьютере — окошко у карточки (`openQuickNote`, Ctrl+Enter сохраняет, Esc закрывает), на телефоне и из профиля — модальное окно `openNoteForm`. Имя автора запоминается (`ft-author`).
- Раскладка, подписи поколений, установка на экран телефона — без изменений (см. историю в README).

## Проверено
- `tests/test.html` — 74 проверки: родство, GEDCOM, сборка payload формы, раскладка на 40 случайных деревьях.
- `tests/worker-test.html` — 94 проверки, в том числе:
  - обновление базы v1 → v2 с сохранением данных; старая заявка;
  - анкеты с новыми людьми; цепочка к неподтверждённой карточке; мгновенные правки своих неподтверждённых данных; правки подтверждённых через админа;
  - заметки и фото «на проверке»; одобрение и отклонение (с удалением файлов); объединение дублей;
  - лимит инструкций на анкету; все прежние проверки защиты;
  - связка `backend.js` и `model.js` с сервером.
  Максимум запросов к D1 за вызов — 33, только при первом создании схемы.
- Вручную в демо: родственник добавляет человека → окно «Готово» → ребёнок к бледной карточке → заметка; админ одобряет, делает «Изменить и принять», данные сохраняются после перезагрузки.

## Локальная разработка
`powershell -ExecutionPolicy Bypass -File tools\serve.ps1` → http://localhost:8790/public/ (демо: код `демо`, пароль админа `demo`; сброс — кнопка в жёлтой полосе). Нужен интернет: sql.js грузится с cdnjs. Node, Python и Git на машине владельца не установлены; файлы на GitHub загружаются через веб-интерфейс.
