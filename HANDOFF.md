# Семейное дерево — заметки для продолжения работы

## Состояние (октябрь 2026)
Сайт полностью готов к развёртыванию на Cloudflare. Инструкция для владельца — `README.md`. KV `family-tree-photos` создан, его ID (`140dd1f4…`) уже вписан в `wrangler.jsonc`. На живом Cloudflare новая версия ещё не запускалась: осталось задать секреты и загрузить файлы на GitHub.

## История решений
- Старая версия (`Sonnet work/`, Worker + D1) не работала из-за ошибки в коде: семейный код «Наша семья» уходил в HTTP-заголовке `X-Auth`, а браузер не пропускает там кириллицу. Плюс коды лежали открытым текстом в публичном репозитории.
- Сначала сделали версию на Supabase + GitHub Pages, но владелец выбрал Cloudflare: проект не засыпает, лимиты щедрее, аккаунт и автодеплой из GitHub уже есть. Supabase-код удалён.
- Фото — в **Workers KV**, а не в R2: для R2 Cloudflare требует банковскую карту, а российские карты не принимаются.
- Дизайн «Скандинавский свет» выбран из трёх концепций (артефакт https://claude.ai/artifact/EXuQ79RuJ6HGjKd5Qby9JC): светлая берёзовая основа, белые вертикальные карточки с круглым фото, полосы поколений с подписями десятилетий, хвойный акцент `#1E5A48`, шрифт Golos Text.
- Родственники входят по общему семейному коду, администратор один — по паролю (секрет `ADMIN_PASSWORD`).
- Родственники в РФ, `*.workers.dev` открывается у них через VPN. Свой домен на Cloudflare не поможет: Cloudflare в РФ замедляют с июня 2025.

## Архитектура
- `wrangler.jsonc`: Worker `gross-tree`, `main: src/worker.js`, статика из `./public` (серверный код наружу не попадает), D1 `DB` (`family-tree-db`, id `3384397a-…`), KV `PHOTOS`.
- `src/worker.js` обрабатывает `/api/*` и `/photos/*`, остальное отдаёт статика Cloudflare. Таблицы создаются автоматически: `ensureSchema`, `settings.schema_version`.
  - Сессии — cookie `ft_s` (семья, 180 дней) и `ft_a` (админ, 30 дней), HttpOnly/Secure/SameSite=Lax. В таблице `sessions` хранится SHA-256 токена.
  - Семейный код: сначала из секрета `FAMILY_CODE`. После смены на сайте — соль + SHA-256 в `settings`, все семейные сессии сбрасываются.
  - Ограничение подбора по `CF-Connecting-IP` (таблица `attempts`): 30 ошибок кода или 10 ошибок пароля в час.
  - Изменяющие запросы проверяют `Origin`. Загрузки — только JPEG до 4 МБ (проверка сигнатуры). Ключи KV вида `p/<uuid>.jpg` и `p/<uuid>_t.jpg`, учёт загрузок — в таблице `uploads`.
  - На бесплатном D1 не больше 50 запросов за вызов: списки обрабатываются пачками через `IN (…)`, импорт идёт одной инструкцией на таблицу через `json_each(?)`.
- Фронтенд — ES-модули без сборки. `backend.js`: `CloudflareBackend` (fetch к `/api`) и `DemoBackend` (localStorage). Демо включается само, если `/api/session` не отвечает JSON-ом (локальный просмотр).
- Единый формат изменений («payload») для заявок и прямых правок админа: `{ person, relations: { add, remove, update }, photos }`, применяется на клиенте в `apply.js` через админские API.
- Раскладка (`layout.js`): блоки «человек + супруги», упаковка по контурам строк. Человек из другой ветки показан «отсылкой» (`ghost`). Карточки 140×156, линия супругов на уровне фото (`partnerY`). `layout.rows` даёт ряды для полос поколений. Подписи десятилетий считаются по медиане годов рождения ряда и рисуются в слое `#genLabels` поверх, оставаясь у левого края.

## Проверено
- `tests/test.html` — 74 проверки: родство, GEDCOM (включая Windows-1251), сборка payload формы, раскладка на 40 случайных деревьях.
- `tests/worker-test.html` — 75 проверок: Worker в браузере, D1 через sql.js (настоящий SQLite), KV в памяти. Покрыты все API, сессии, смена кода, ограничение подбора, Origin, загрузка и раздача фото, каскадное удаление (человек с 30 фото), импорт и экспорт. Отдельно — связка клиентского `backend.js` и `apply.js` с сервером. Максимум запросов к D1 за вызов — 17 (лимит 50).
- Визуально в демо: дерево, профиль, анкета, админка, телефон.
- **Не проверено на живом Cloudflare**: реальные D1/KV, поведение cookie на `workers.dev`, применение `_headers`.

## Что можно сделать дальше
1. Уведомления админу о новых заявках в Telegram (вызов Bot API из Worker при `POST /api/submissions`, токен в секрете).
2. Календарь дней рождения и памятных дат.
3. Восстановление из JSON-бэкапа; скачивание всех фото архивом; очистка неиспользуемых загрузок (таблица `uploads` уже есть).
4. Отметка людей на групповых фото, карта мест рождения, тёмная тема.
5. Раскладка «Вся семья»: если у обоих супругов есть родители в дереве, одна ветка показывает отсылку. Можно попробовать тянуть линию к основной карточке.

## Локальная разработка
`powershell -ExecutionPolicy Bypass -File tools\serve.ps1` → http://localhost:8790/public/ (демо: код `демо`, пароль админа `demo`). Node, Python и Git на машине владельца не установлены; файлы на GitHub загружаются через веб-интерфейс.
